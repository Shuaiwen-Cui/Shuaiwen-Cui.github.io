# 仿真与虚实迁移

!!! abstract "这一页解决什么"
    仿真里成功不等于真机成功。这一页讲怎样缩小仿真与现实的差距、怎样在资源受限的硬件上部署、怎样分阶段验证。**进阶**：在 E3 能稳定复现之后深入；你的数字孪生到现场（自适应触发项目）和端侧部署经验在这里直接可用。

## 核心知识

**现实差距（reality gap）**：仿真与真机在动力学（摩擦、质量、延迟）、感知（光照、噪声、相机参数）和执行（电机响应、齿隙）上都有差别，策略会利用仿真中不存在的漏洞。

**域随机化**：训练时随机化摩擦、质量、光照、纹理、相机位置等，让真实世界看起来只是又一次随机采样。简单有效，代价是策略变保守、训练更久。

**系统辨识**：用真机数据估计仿真参数，让仿真更像真机。与域随机化互补：先辨识缩小差距，再在辨识值附近随机化。这和你的结构模态辨识是同一类问题。

**可微仿真**：仿真对参数可求导，可以用梯度直接拟合真机轨迹或优化策略；接触不连续时梯度不可靠。

**分阶段验证**：软件在环（算法 + 仿真）→ 硬件在环（真实控制器 / 计算单元 + 仿真）→ 受控真机 → 开放环境。每一步只换一个因素，失败才好归因。

**实时性与资源预算**：控制频率、端到端时延、算力和功耗共同约束模型大小。量化、蒸馏和算子优化决定策略能不能在机载计算单元上按时运行。

**安全与失效处理**：动作限幅、速度限制、急停、看门狗超时、异常检测后的安全姿态。上真机前必须先有这些。

**评测为什么难**：真机实验慢、初始条件难复现、环境会变，所以要固定初始状态集、记录每次失败类型，并报告"成功次数 / 总次数"而不是单一百分比。

## 路线之争 · 真机数据 vs. 仿真数据

真机派认为仿真永远不够真，直接在真机上采集遥操作数据最可靠，成本靠规模化降下来；仿真派认为只有仿真能提供 RL 所需的数据量和安全性，渲染与物理越来越真。实践中：运动与平衡偏仿真 + RL，精细操作偏真机演示，两者混合训练正在成为常态。

## 自测

??? question "域随机化的范围设得太大会怎样？"
    策略要在所有极端情况下都能工作，会变得过于保守、性能下降，训练也更难收敛。范围应覆盖真实参数的不确定性，而不是越大越好。

??? question "系统辨识和域随机化是什么关系？"
    互补。辨识把仿真参数拉近真机的中心值，随机化覆盖剩余的不确定性；先辨识再在其附近随机化通常效果最好。

??? question "硬件在环验证了什么、没验证什么？"
    验证了真实计算单元上的时延、算力和接口；没验证真实物理交互（接触、摩擦）和真实传感器噪声。

??? question "为什么真机评测要报告成功次数 / 总次数，而不是单个成功率？"
    真机试验次数少，20 次中成功 16 次和 200 次中成功 160 次的可信度不同；还要说明初始条件和失败类型。
